## Context

**"okay get rid of this engaged metric" / "and can we standardize what units rmsd
is reported in"** — @twu383, 2026-09-10, mid-presentation-prep.

Two fields carried the word "engaged" and neither measured warhead engagement:
`shared/gromacs_analysis.py`'s `explicit_frac_frames_engaged` (explicit-solvent
100 ns runs) and `shared/md_ensemble.py`'s `frac_frames_engaged` (implicit-
solvent runs). Both measure the same thing — the fraction of frames retaining
at least a quarter of the STARTING PROTEIN CONTACTS — which is whether the
ligand stayed in the pocket. The geometry question, whether the reactive atom
reached Cys113, is a completely different computation
(`attack_sweep.frac_attack_ready`, distance- and angle-gated against the sulfur).

This is the FOURTH time the collision has produced a wrong reading:

1. The 2.2.0 record for `t4_716800c125a7` quoted **98.45% / 99.80% "target
   engagement"** — this field, not geometry. No 100 ns geometry run for that
   molecule exists anywhere on disk.
2. `t4_88ae42890e2d_m239` (D0114): 99.6% on this field, 8.0% on the real one —
   held the pocket while the warhead rotated away.
3. `t4_7b02d1dc4fd2_m50` replicate 2 (D0118): 99.6% on this field, 0.0% on the
   real one — the warhead never once entered the attack window in 100 ns, and
   reading the residence number as engagement made the failed replicate look
   like a confirmation of the successful one.
4. `scripts/shortlist_report.py` rendered it under the literal label
   **"target engagement, 100 ns"** on the candidate dossier page — the exact
   phrase from instance 1, generated by the exact code this record fixes.

Separately: RMSD was reported in nanometres from the explicit/implicit-solvent
path (`*_rmsd_nm_*`) and Angstrom from the attack-sweep path (`rmsd_max_a`,
already following the convention stated in `attack_sweep.rmsd_stats`'s own
"UNITS ARE THE TRAP" docstring). `scripts/shortlist_report.py`'s candidate
dossier showed both on ONE page: RMSD in nm three rows up, a distance in
Angstrom a few rows down.

## Decision

**Renamed at the single source of truth in both files:**

- `explicit_frac_frames_engaged` → `explicit_frac_frames_resident`
  (`shared/gromacs_analysis.py`)
- `frac_frames_engaged` → `frac_frames_resident` (`shared/md_ensemble.py`)
- `ENGAGED_FRACTION` → `RESIDENT_CONTACT_FRACTION` (the shared 0.25 threshold)

Propagated mechanically to every consumer (15 files) — column reads, log
lines, and every human-facing label ("target engagement, 100 ns" →
"pocket residence, 100 ns"; "X% engaged" → "X% resident"; dict keys "frames
engaged"/"engaged" → "frames resident"/"resident"). The geometry metric
(`frac_attack_ready`, `engagement_rank.py`, `nac_screen_v2.py`'s `engagement`
column, `attack_sweep.py`'s `warhead_engaged`) is untouched — it is correctly
named and must stay "engagement".

**RMSD standardised on Angstrom for every DISPLAY site.** Angstrom companions
(`_a` suffix, nm * 10) were added beside every `_nm` field at its point of
computation — `gromacs_analysis.analyse()`, `md_ensemble.residence_metrics()`,
`mdprio_report.residence()`, `pipeline.survivors()` — and every renderer
(`shortlist_report`, `replicate_report`, `control_stub_report`,
`mdprio_combine`, `md_residence_3ikd`, `promote_to_bpmd`, `run_md_ensemble`,
`app.py`) now reads the `_a` field. **The `_nm` fields are kept, not removed**:
`shared/pipeline.py`'s survivor gate and `shared/residence_tier.py`'s tier
boundaries are both stated in nm against an nm config threshold
(`md_survivor_rmsd_nm`), and converting the gate itself was out of scope and
higher-risk than the display fix asked for. `mdprio_combine.py`'s rail prefers
a `.tier.json` sidecar's `_a` field when present and falls back to `_nm * 10`
for sidecars written before this record — the ~2,000 already on disk.

## Consequences

**Caught one live NameError while propagating the rename** — two references to
the old `eng` local variable at `mdprio_combine.py`'s row-rendering loop
(`data-eng='{eng...}'` and the bar-width span) would have raised on the very
page this session was about to hand to the user, since the sed rename left
those in an unrenamed scope. Full test suite (191 passed) plus the
streamlit-`AppTest` GUI suite (`tests/run_gui_env.sh`) both re-run clean after
the fix.

**Also caught D0118's own frontmatter missing the required `approach` field**
while running the GUI suite — it broke the Decisions and Open-questions panels
outright (`DecisionError: missing field(s) ['approach']`). Fixed alongside
this record.

Every future 100 ns run now writes both units and the correctly-scoped name.
Nothing that reads the OLD `_nm`/`_engaged` names from an existing CSV breaks —
this is additive at the source, renamed only at the display layer plus the
column name itself (which every consumer was updated to follow).

## What is NOT fixed

`shared/pipeline.py::survivors()`'s bare `rmsd_max`/`rmsd_mean` columns (no
unit suffix at all — a related but distinct instance of the same disguise,
category 1 in `how_this_project_breaks.md`) still gate in nm internally; only
their new `_a` companions are used for display. Renaming the gate itself
touches `tc.md_survivor_rmsd_nm()` and the comparison at
`survivors()`'s return line — left alone as a separate, lower-urgency change.
